# 服务器应用管理面板 · 开发方案（v1，待确认）

> 目标：在 192.168.1.5 上自建一个 Web 面板，可视化查看/管理服务器所有应用（端口、部署、显存/内存、路径、启停、实时日志、网页直达），SQLite 存储，带登录。
> 状态：**方案待用户确认，确认后开发。**
> 设计原则：能落地、可操作、隔离部署（不碰现有服务）、留后路可回滚。

## 一、技术选型（结论先行）

| 层 | 选型 | 理由 |
|----|------|------|
| 后端 | **FastAPI (Python 3.12)** | 必须——启停/显存/日志是系统级操作，只能由后端调 systemctl/nvidia-smi 完成；与服务器现有 douyin-web/voice-server 同栈，你熟 |
| 数据库 | **SQLite** | 你要的，单文件，零运维；登录账号存在 SQLite 的 users 表里 |
| 前端 | **Vue 3 + Element Plus + ECharts（响应式）** | 现成开源框架，卡片/表格/弹窗/登录全是现成组件，样式好看；一套代码自动适配 PC 和手机 |
| 系统操作 | `systemctl` + `journalctl` + `docker` + `nvidia-smi` + `ps` | 直接调系统命令，实时准确 |
| 实时日志 | **SSE（Server-Sent Events）** | 比 WebSocket 简单，够用 |
| 部署 | **systemd 新服务 + 独立 venv + 独立端口** | 隔离，不碰现有服务 |

> 分工明确：**后端必须 Python（FastAPI）** 干脏活（读状态/启停/日志/鉴权），**前端用 Vue3+Element Plus 开源框架**做展示交互。纯 HTML 做不了系统操作。

│  systemctl / journalctl / docker /          │

└─────────────────────────────────────────────┘

## 四、API 设计

| 方法 | 路径 | 功能 |
|------|------|------|
| POST | /api/auth/login | 登录，返回 JWT |
| GET | /api/auth/me | 当前用户 |
| GET | /api/overview | GPU 总账 + 内存总账 |
| GET | /api/apps | 应用列表（含实时状态：运行/端口/显存/内存/健康） |
| POST | /api/apps/{id}/start | 启动 |
| POST | /api/apps/{id}/stop | 停止 |
| POST | /api/apps/{id}/restart | 重启 |
| GET | /api/apps/{id}/logs | SSE 实时日志 |
| GET | /api/apps/{id}/status | 单应用实时状态 |
| GET | /api/system/services | 扫描可选 systemd/docker（供添加应用） |

**状态采集**（后端定时，如每 5s，前端轮询 or SSE 推）：
- `nvidia-smi --query-compute-apps=pid,process_name,used_memory` → 按 PID 匹配服务显存
- `ps -o pid,rss,comm -p <pid>` → 内存
- `ss -tlnp` → 端口监听
- `systemctl is-active` / `docker ps` → 运行状态
- `curl -s http://127.0.0.1:{port}/health` → 健康

## 五、前端页面设计（Vue3 + Element Plus，响应式，PC/手机自适应）

**布局**：Element Plus 响应式（`el-row`/`el-col`，xs/sm/md/lg 栅格），PC 卡片一行 3-4 个，手机一行 1-2 个，自动适配。

- **登录页**：居中卡片，账号/密码（存 SQLite users 表），默认 `admin / 123456`
- **总览顶栏**：GPU 总显存分配饼图（ECharts）+ 内存占用 + 服务总数/运行数
- **应用卡片网格**：每个应用一张卡片（独立区域块，`el-card`），含：
  - 图标 + 应用名 + 分组标签
  - 状态点（绿=运行/健康，红=停止，黄=异常）
  - 端口、部署方式、路径、显存/内存占用
  - 按钮：`启动`/`停止`/`重启`、`日志`、`访问`（网页直达）
- **日志弹窗**：点日志弹出 `el-dialog`，实时滚动（SSE），可清空/复制
- **分组筛选**：顶部 tab（全部/AI/数据库/Docker/Web）

## 六、权限方案（关键，二选一）

| 方案 | 做法 | 优点 | 缺点 | 推荐 |
|------|------|------|------|------|
| **A. sudoers 白名单**（推荐） | 只给 `ubuntu` 用户 NOPASSWD 执行 `systemctl start/stop/restart` + `journalctl` + `docker`，后端以 ubuntu 运行 | 最小权限、安全 | 需写 sudoers 规则 | ⭐ |
| B. 后端以 root 运行 | FastAPI User=root | 简单 | 面板一旦被攻破=整机沦陷 | ✗ |

> 默认走 A：新增 `/etc/sudoers.d/app-panel`，仅允许面板调用指定的 systemctl/docker 命令，不放开 root shell。

## 七、部署方式（隔离 + 可回滚）

```
/opt/app-panel/            # 代码
/opt/app-panel-venv/       # 独立 venv（Python 3.12）
/opt/app-panel/data.db     # SQLite
/etc/systemd/system/app-panel.service
/etc/sudoers.d/app-panel   # 权限白名单
```

**systemd 单元**：
```ini
[Unit]
Description=App Management Panel
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/opt/app-panel
ExecStart=/opt/app-panel-venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8085
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

- **端口 8085**（已勘察，未占用）
- 前端静态文件由 FastAPI 托管
- 安装脚本幂等可重跑；卸载脚本完整回滚

## 边界与风险（诚实说明）

- 面板本身能启停系统服务，**必须登录 + 建议只绑内网**（本机已 0.0.0.0 但你服务器在内网，风险可控）
- 首次开发我建议**先在本地/测试跑通再上服务器**，避免一上来就动生产环境
- 数据全部来自实时系统命令，不编造；个别服务无 /health 则健康状态显示"未知"
- 卸 1Panel 已回滚，服务器现在无面板，随时可开工
